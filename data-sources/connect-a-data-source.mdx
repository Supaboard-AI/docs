Connect the database or warehouse that holds the information you want to analyze. Once the connection is ready, Supaboard can use it in questions, queries, and artifacts.

## Before you begin

You need permission to add data sources. For a database, ask the person who manages it for its connection details and the approved network access method. Use the [connector-specific guide](/data-sources/overview#available-connectors) for required fields and permissions. Your plan sets how many data sources the workspace can connect; see [Data source limits](/data-sources/overview#data-source-limits).

## 1. Choose the connector

Open **Data sources → Connect Data Source**. Search for your database or warehouse, or browse **Databases**.

  <img src="/images/guides/connector-picker.png" alt="Connect your data source dialog with database and app connectors" />
</Frame>

## 2. Complete setup

Give the connection a name your team will recognize. For a database, enter its connection URL or the requested host, database, username, and password. Configure SSL and any tunnel or VPN required by your network.

The database form shows Supaboard IP addresses to allow in your firewall. Copy the current list from the form rather than using addresses from a screenshot.

New Fivetran app connections can't be created. Existing ones keep working; see [Existing Fivetran connections](/data-sources/overview#existing-fivetran-connections).

## 3. Connect and wait for discovery

Choose the connector's **Connect** button. Supaboard checks the connection and discovers its schema—the tables and columns it can use. Some sources need time for an initial sync or schema preparation.

If setup fails, check the error against the connector's troubleshooting section before trying again.

## 4. Check the tables and agent access

Open the new source and confirm the tables you expect are present. In **Settings → Connections**, review its connection details, table context, and instructions when needed.

Make sure the agent you will use has access to this source. A working connection does not override a teammate's resource restrictions or an agent's data scope.

## Expected result

The source appears in **Data sources**, the intended tables are available, and your chosen agent can answer a simple question using them.
